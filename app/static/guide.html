Calling the API from another service

Base URL: {{BASE}}. The caller must be able to reach this address. By default the server listens only on 127.0.0.1. To accept requests from other machines, set HOST=0.0.0.0 in .env, and also set TTS_API_KEY.

Contents

    Authentication

    If the server has TTS_API_KEY set, send it on every request as Authorization: Bearer <key>. A missing or wrong key returns 401.

    Endpoints

    MethodPathPurpose
    GET/v1/voicesLists the voices. Pass a data[].id as voice. If you leave voice out, the server uses default.
    POST/v1/audio/speechTurns text into audio.
    POST/v1/voicesClones a voice. Multipart form: name (1–40 letters, digits, spaces or - _ . ( )), file (3–8 s, up to 5 MB; WAV, FLAC, OGG or MP3, or any format when the server has ffmpeg), optional denoise (default true), gender, description. The new voice is usable right away by its name.
    DELETE/v1/voices/{id}Removes a cloned or LoRA voice. Built-in voices cannot be removed (403).
    GET/v1/voices/{id}/clipThe reference clip a cloned voice was made from (WAV).
    LoRA training (GPU only; see Train a LoRA voice)
    GET/v1/lora/sessionsLists training sessions (without their clips) and the server's limits.
    POST/v1/lora/sessionsStarts a session. JSON {"name", "gender", "description", "mode"}: "record" (default) reads the server's script, "import" brings your own clips and transcripts.
    POST/v1/lora/autoStarts a session from one long recording (AI method). Multipart file, name, optional gender, description.
    GET/v1/lora/autoWhether the speech-to-text server is reachable, and the upload limits.
    GET/v1/lora/sessions/{id}One session: status, its sentences with clips, and training or transcription progress. Poll it.
    PUT/v1/lora/sessions/{id}/clips/{i}Record mode: saves (or replaces) the clip of sentence i. Multipart file, 1–20 s.
    POST/v1/lora/sessions/{id}/clipsImport mode: adds a clip with its transcript. Multipart file (1–20 s), text (up to 500 characters).
    PATCH/v1/lora/sessions/{id}/sentences/{i}Import mode: fixes a transcript. JSON {"text"}.
    GET, DELETE/v1/lora/sessions/{id}/clips/{i}Downloads a clip (WAV), or removes it. In import mode its transcript goes too, and later clips move up one index.
    POST/v1/lora/sessions/{id}/trainQueues training. JSON {"denoise": true} (optional). Record mode needs every sentence; import mode needs at least 5 clips.
    DELETE/v1/lora/sessions/{id}Deletes the session, its clips and its model, stopping any running job.
    GET/healthStatus and device (no key needed). Returns 503 while the model loads.

    Request body for POST /v1/audio/speech

    FieldRequiredMeaning
    inputyesThe text to read, up to 20,000 characters.
    voicenoA voice id from /v1/voices. Leave it out to use the default voice.
    response_formatno"wav" (default) returns one complete file. "pcm" streams raw audio as it is generated.
    deviceno"gpu" or "cpu". Leave it out to use the server default (TTS_DEFAULT_DEVICE). LoRA voices always run on the GPU and return 400 for "cpu". The first request for a device that is not loaded yet waits while it loads. The response header X-Device says which device ran the request.
    modelnoAccepted for OpenAI compatibility ("vieneu-v3-turbo").

    The server reads text exactly as written. It does not convert numbers, dates, times or licence plates to words, so write them out (for example "mười giờ" instead of "10:00").

    Which method to use

    File (wav): the response arrives after the whole text has been synthesized, as a normal WAV file (48 kHz, mono, 16-bit). Use it when you need to save or send a file.

    Stream (pcm): audio starts arriving after about 0.1 s and keeps coming while it is generated. Use it to play speech with the least delay. Both methods take the same total time; only the wait for the first sound differs.

    The stream is raw PCM: 16-bit signed little-endian, mono. The sample rate is in the X-Sample-Rate response header (48000). The stream has no file header, so to save it as a file, add a 44-byte WAV header with that rate. A chunk can end halfway through a 2-byte sample; if so, carry the odd byte into the next chunk.

// A page on another domain needs that domain in ALLOWED_ORIGINS on this server.
async function streamSpeech(input, voice) {
  const res = await fetch("{{BASE}}/v1/audio/speech", {
    method: "POST",
    headers: { "Authorization": "Bearer {{KEY}}", "Content-Type": "application/json" },
    body: JSON.stringify({ input, voice, response_format: "pcm", device: "{{DEVICE}}" }),
  });
  if (!res.ok) throw new Error((await res.json()).error.message);
  const rate = Number(res.headers.get("X-Sample-Rate")) || 48000;
  const ctx = new AudioContext();
  const reader = res.body.getReader();
  let nextTime = 0, carry = null;
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    let bytes = value;
    if (carry !== null) { bytes = new Uint8Array([carry, ...value]); carry = null; }
    if (bytes.length % 2) { carry = bytes[bytes.length - 1]; bytes = bytes.subarray(0, -1); }
    if (!bytes.length) continue;
    const view = new DataView(bytes.buffer, bytes.byteOffset, bytes.byteLength);
    const buffer = ctx.createBuffer(1, bytes.length / 2, rate);
    const ch = buffer.getChannelData(0);
    for (let i = 0; i < ch.length; i++) ch[i] = view.getInt16(i * 2, true) / 32768;
    const src = ctx.createBufferSource();
    src.buffer = buffer;
    src.connect(ctx.destination);
    if (nextTime < ctx.currentTime) nextTime = ctx.currentTime + 0.12;  // small buffer against gaps
    src.start(nextTime);
    nextTime += buffer.duration;
  }
  return ctx;  // ctx.close() stops playback; reader.cancel() also tells the server to stop generating
}

    Train a LoRA voice

    A LoRA voice is the model fine-tuned on one speaker. It sounds closer to the speaker than a clone, but training needs the server's CUDA GPU, and the voice runs on the GPU only. There are two ways to give the server training data. Both end in the same kind of session and the same training call.

    • Manual: either read the server's 14-sentence script ("mode": "record", about a minute of speech), or bring your own clips of one sentence each with their transcripts ("mode": "import", 5–1000 clips of 1–20 s).
    • AI: upload one long recording of one speaker. The server cuts it at the pauses into clips of 3–15 s, and the speech-to-text server at TTS_STT_URL transcribes each clip. Check GET /v1/lora/auto first: stt_available must be true, or the upload returns 503.

    Then poll GET /v1/lora/sessions/{id} every few seconds and follow status:

    statusMeaning
    transcribingAI method only: the recording is being split and transcribed. auto holds stage (queued, decoding, splitting, transcribing, then done or failed), done, total, kept and message. Clips appear in sentences as they are transcribed.
    recordingClips can be added, changed or removed, and training can start. After a failed transcription, error says why, and the clips found so far are kept.
    queued, trainingA training job owns the session. queue_position is 0 while it trains. progress holds stage (preparing, training, saving), step, total_steps, loss and eta_s (seconds left).
    readyDone: the voice is in /v1/voices with "lora": true. Use its name as voice, with "device": "gpu".
    failedTraining failed; error and log say why. Clips can change again, and /train starts it again.

    Speech recognition makes mistakes, and the model learns exactly what the transcripts say. Before training an AI session, read sentences[].text, fix wrong words with PATCH, and delete clips with other voices, music or cut-off words. The LoRA training (AI) page does this with a player. The model also reads text as written, so numbers in transcripts should be spelled out ("mười giờ", not "10 giờ").

    Clips can be WAV, FLAC, OGG or MP3, or any format the server's ffmpeg reads. Mono recordings without music or background voices work best. More speech gives a closer voice: one minute works, and 10–30 minutes is best. Training takes a few minutes for a minute of speech, and longer for more. Only one training job runs at a time; the others wait in the queue.

    import time
import requests

BASE = "{{BASE}}"
H = {"Authorization": "Bearer {{KEY}}"}

def check(res):
    if not res.ok:
        raise RuntimeError(res.json()["error"]["message"])
    return res.json()

def wait(sid, busy):
    """Poll the session until its status leaves `busy`."""
    while True:
        s = check(requests.get(f"{BASE}/v1/lora/sessions/{sid}", headers=H, timeout=30))
        if s["status"] not in busy:
            return s
        print(s["status"], s.get("auto") if s["status"] == "transcribing" else s.get("progress"))
        time.sleep(5)

# 1. Upload one long recording of one speaker (any audio format).
with open("speaker.mp3", "rb") as f:
    s = check(requests.post(f"{BASE}/v1/lora/auto", headers=H, timeout=600,
                            data={"name": "Lan (LoRA)", "gender": "female"},
                            files={"file": ("speaker.mp3", f)}))
sid = s["id"]

# 2. Wait for it to be split and transcribed.
s = wait(sid, ["transcribing"])
if s["error"]:
    print("transcription stopped:", s["error"])
print(s["sentences_recorded"], "clips,", s["recorded_seconds"], "s of speech")

# 3. Review: fix wrong transcripts, drop bad clips (highest index first, as later indexes shift).
for x in s["sentences"]:
    print(x["index"], f'{x["clip"]["seconds"]:.1f}s', x["text"])

    Errors

    Errors are JSON in OpenAI's format: {"error": {"message": "...", "type": "invalid_request_error", "code": 400}}.

    StatusMeaning
    400Bad request: empty input, unknown voice, or unsupported response_format.
    401Missing or wrong API key.
    404A voice, LoRA session or clip that does not exist.
    409A voice name that is already taken, or changing a LoRA session while it is transcribing, queued, training or ready.
    413Upload too large: clone clip over 5 MB, LoRA clip over 8 MB, or long recording over TTS_AUTO_MAX_MB (500 MB by default).
    429Server busy. Retry after the number of seconds in the Retry-After header.
    503Model still loading, or (for POST /v1/lora/auto) the speech-to-text server is not reachable.

    The code samples fill in this server's address and the key, voice and device last chosen on the test page (the key shows as <your-key> when none is saved).
